# 筆記撰寫規範

guideline_version: 1.4

版本資訊：1.4 把 L3 教科書筆記累積的正確性規則移植成講座用語（讀者層級、名詞小辭典、正確性清單、
台灣譯名、獨立驗收），並加上 R12 到 R14。與 obsidian-v4-cleanup task5 規則各自維護；本版對應 task5 2026-10 版。

這份規範是 lecture2notes 的產品的一部分，不是內部備忘。`l2n render` 產出的骨架筆記由語言模型就地擴寫，擴寫者可能是 Claude Code、也可能是任何一個讀得懂這份文件的模型；這份文件就是它們之間唯一的合約。

規範分成兩部分，界線很明確：

- **LLM 必須遵守**：人類與模型共同遵守的寫作規則。有些條目機器判不出來，靠的是寫的人自己守。
- **機器可檢查**：`l2n check note` 真的會跑、會報、會讓 exit code 變成 1 或 2 的規則。

兩份都要讀。只讀第二部分會寫出「通過檢查但沒有價值」的筆記；只讀第一部分會寫出「看起來不錯但原話直貼」的筆記——本專案已經反覆遇過後者，所以才有第二部分。

觀念來源：《防彈筆記法》（一則筆記要有明確用途）、《如何閱讀一本書》（分析閱讀的四個問題）、《研究生完全求生手冊》（貢獻三格：問題、方法、差異）、《巨人的筆記》（記下來只是開始）、《邊寫邊思考的大腦整理筆記法》（寫是思考的動作，不是保存的動作）。這些書談的是人怎麼做筆記；本規範把其中能落到機器上的部分落到機器上。

## LLM 必須遵守

### 0. 不做的開關

這一節排在最前面，因為它決定後面幾節要不要執行。

#### 0.1 Step 0 分流：先填貢獻三格

擴寫之前，先用骨架、逐字稿與講義回答三個問題：

1. **問題**：這場講座解決了什麼別人沒解決、或沒說清楚的問題？
2. **方法**：它用什麼方法、什麼判準、什麼證據來解決？
3. **差異**：它跟你已經知道的東西差在哪？哪一句話會改變你之後的做法？

三格都填得出來 -> 照規範做完整擴寫。
**任何一格填不出來 -> 停在骨架，只補一段「檢索摘要」（這場在講什麼、關鍵字、時間碼，供日後回頭找），不做完整擴寫。**

不是每一場講座都值得一份 faithful 全量筆記。一份沒有貢獻的講座做成完整筆記，代價是日後每次搜尋都要多篩一份雜訊。停在骨架不是偷懶，是正確答案。

#### 0.2 Step 0 第三層：產物型態

貢獻三格過了，還有第三個問題要答：**這場講座該產出什麼型態的東西？**

判準是這場講座教的是**流程**還是**機制**：

| 講座在教什麼 | 該產出什麼 |
| ---- | ---- |
| 「看到 X 就判斷 Y」的對應關係，而且這個題材對你已經自動化（讀起來完全順暢、不用停下來想） | **不做完整筆記**。留骨架與檢索摘要就好。 |
| 「看到 X 就判斷 Y」，但這個題材你還會卡 | 做完整筆記。 |
| 為什麼會這樣、判準是怎麼推出來的（機制） | 做完整筆記，而且重點放在推理鏈。 |

已經自動化的對應關係寫成筆記，日後不會有人回去看——你不看是因為你本來就會了，而它還是佔著搜尋結果。

**以題材為單位，不以專科為單位。** 同一個人在同一個專科裡，有些題材已經自動化、有些還沒有；用專科一刀切，會把還會卡的題材一起丟掉。逐場判斷，不要預設立場。

#### 0.3 禁止補位，也禁止編造

筆記裡的每一行都必須有出處（見第 1 節）。由此推出兩條硬規則：

- **不可編造**：任何講義、影格、逐字稿都查不到的內容，一律不寫進本文。不確定的術語走 `unverified_terms`。
- **不可補位**：任何章節沒有素材，就**留空或直接刪掉那一節**。不得填 `N/A`、`不適用`、`無資料`、`（略）`，也不得為了湊行數補一段教科書套語。

這兩條是同一件事。理由是：AI 補出來的通用套語，和有出處的內容在筆記裡長得一模一樣，讀者三個月後分不出哪一行可信。一節空著，讀者知道那裡沒東西；一節填著看似合理的套語，讀者會以為講者說過。空白是誠實的，補位不是。

`l2n check note` 的 R8 會抓最明顯的補位字串，但它只抓得到字面；套語抓不到，靠你自己。

1.4 起這兩條有三個寫明的例外，除此之外沒有別的：

- **名詞小辭典**（0.11）：唯一允許非講者內容的地方，標題就寫明「非講者內容」。它解釋的是**詞**，
  不是講者沒講的主張。
- **`N/A（原文未涵蓋）`**：一字不差的這個字串，只用在 `# 閱片` callout 的固定欄位，意思是
  「我查過了，講者沒講」。Note 段落沒素材就整段不存在，**不用它**。
- **標了記號的推論**（2.2）：本文的推論只認 `[推論]` 與 `[本筆記整理]` 兩種記號。
  **沒有記號的推論就是編造。**

讀者層級（0.10）不放寬這一節：寫給國高中生看，也不能補講者沒講的內容。

#### 0.4 「一個都不能丟」只適用於數值與判準

值得逐項保留、一個都不能漏的，是**數值與判準**：

- 分級、分類、期別
- 閾值、切點、界線數字
- 劑量、參數、設定值
- 測量值與單位
- 比較表（A 與 B 的差異欄位）

這些漏一項，筆記就錯了。

**背景敘述不是。** 鋪陳、舉例、寒暄、重複說明、講者的口頭禪，每一節壓到 **150 字以內**。逐字稿不是需要被全數保留的東西，它是素材。把三分鐘的鋪陳寫成三行，是這份筆記存在的理由。

#### 0.5 骨架不是成品，擴寫完也還不是成品

`l2n render` 的輸出是**工作底稿**。它有正確的章節、正確的時間碼、正確的影格位置，但它還不是筆記。

擴寫完成之後，它是**一份 AI 寫完的稿**。這跟「讀者消化過的筆記」是兩件不同的東西，中間差的那一步沒有任何模型能代勞。規範把這件事寫出來，是為了讓所有人（包含模型自己）不要把第二階段當成終點。

想把這件事記在 frontmatter 上的人，可以在自己的 overlay 模板加一個欄位，例如 `消化層級`：`0` 未處理、`1` AI 寫完沒人看、`2` 看過但沒留下自己的字、`3` 留了自己的字。**模型產出一律填 `1`**，升級只能由讀者自己做。這個欄位屬於個人 vault 慣例，跟 `noteVer`、`subspecialty` 一樣只寫在自己的 `note.frontmatter.yaml`，不進公開版的 generic 模板。

#### 0.6 「我應該記住的 3 件事」只能是草稿，而且是摺起來的草稿

骨架在「學習驗證」節裡預先寫了 3 條候選，整組收在一個摺疊區塊裡：

```
> [!note]- 模型候選（未經本人確認）
```

- 模型的工作：把這 3 條寫成具體、可檢驗、看得出這場講座特色的句子。**不要把摺疊拿掉。**
- 讀者的工作：**保留、刪除或改寫**。三選一，沒有第四個選項。

摺疊不是排版，是設計。一份已經填滿、攤開在眼前的清單，讀者最省力的處置是「看起來都對，不動它」；一份摺起來的清單，要用到就得先動手打開。

##### `<!-- ai-draft -->` 標記什麼時候在、什麼時候不在（1.3 定案，1.4 沿用）

1.2 以前這裡寫著「標記會留在檔案裡」，而「完成的定義」那一節又要求
`ai_draft_remaining=0`，兩句話互相牴觸，做的人照哪一句都是錯的。1.3 的定案（1.4 沿用）是：

- **標記的意思只有一個：這一格還等著模型寫。** 模型把那一格寫完，就**連同標記一起刪掉**。
  所以骨架裡有標記的只有兩處：`## 講者骨架` 的第三欄、`## 題目` 的答案；讀者層級不是
  `self` 時再加一處：名詞小辭典的條目（0.11）。
- **讀者的東西不帶標記。** Summary 的兩個句首空槽（0.7）與這一節的「模型候選」摺疊區
  **不帶** `<!-- ai-draft -->`：它們不是待模型完成的東西，標了只會讓那個數字永遠歸不了零。
- 因此 **`ai_draft_remaining=0` = 模型該寫的都寫完了**，不多不少。

那讀者到底有沒有碰過這份筆記，靠什麼看？靠 0.8 的首行定位宣告：那一行寫著
「模型產出的初稿，未經本人確認」，**只有讀者自己能改掉它**。

#### 0.7 Summary 區的兩個空槽

骨架會在 Summary 區放兩個空槽，每一個都是一句寫到一半的話，不是一個問句：

```
開這篇之前我卡在___

這篇沒回答到的是___
```

用句首而不用問句，理由跟 0.6 一樣：空白的格子會被跳過，寫到一半的句子會被寫完。

這兩行是給讀者的，**模型不要代填，也不要刪掉**。兩格都填不出來，就選「丟棄」——一份找不到開啟理由的筆記，最好的處置就是丟掉。

#### 0.8 首行定位宣告

骨架的第一行（frontmatter 之後）永遠是：

```
> 本筆記為模型產出的初稿，未經本人確認。
```

**不得刪除，也不得改寫成比較好聽的句子。** 模型填出來的段落和人寫出來的段落，在筆記裡長得一模一樣；三個月後打開這個檔案的人，沒有其他線索可以分辨。這一行就是那個線索。讀者自己確認過之後，可以自行改掉這一行——那是讀者的動作，不是模型的。

#### 0.9 坡道句自檢

「坡道」是一場講座開頭那 5 至 8% 的內容：講者在那裡交代這件事為什麼值得講、前人卡在哪裡、既有做法哪裡不夠。坡道是 Evergreen 的原料——離開這場講座仍然成立的那句話，通常長在坡道裡，不在正文的細節裡。

擴寫之前自問一次：**這篇為什麼值得開？前人卡在哪？** 兩句都寫得出來，照規範做完整擴寫。

寫不出來時不要硬掰一句像樣的話，而是在 Summary 的第一行加上：

```
> [!warning] 降級：本筆記只是資訊重排，未找到問題意識
```

這比一句編出來的坡道句誠實得多。降級標記留著，日後補得出坡道句再拿掉。

#### 0.10 讀者層級

筆記寫給誰看，由 profile 的 `outputs.toml` 決定：

```toml
[note]
reader = "self"   # self | clerk | student | public
```

預設 `self`。`l2n render --expand-prompt` 會印出生效層級的那一列，`l2n profile show` 看得到它來自哪一層。

| 層級 | 讀者 | 詞彙與縮寫 | 名詞小辭典 | 題目型態 |
| ---- | ---- | ---- | ---- | ---- |
| `self` | 筆記主人 | 專有名詞與縮寫保留英文原文（HARD RULE 6），不另加中譯 | 不產生 | 問理由與邊界，至少一題 [推論] |
| `clerk` | 專業入門者 | 首見寫「中文（English, 縮寫）」，之後用縮寫；分級系統名（BI-RADS 等）例外 | 選用 | 同 self，可加一題「把講者的判準套到另一個案例」 |
| `student` | 國高中生 | 首見寫「中文（English, 縮寫）」，縮寫一律展開（分級系統名例外）；能用中文說的就用中文 | 必須有 | 先問「講者說了什麼、為什麼」，再一題 [推論]；不考專業細節的記憶 |
| `public` | 一般大眾 | 同 student（分級系統名例外），而且英文只放在首見的括號裡 | 必須有 | 生活情境題，至少一題 [推論]；不用術語出題 |

- 「首見」包含 Evergreen、Summary 與骨架裡的 `takeaways_zh`；縮寫要在 JSON 階段就展開，
  Summary 才能照 7.1 逐字引用（見 `skill/references/segmentation.md`）。
- 只用講者或講義用過的縮寫；他們沒用的縮寫直接寫全名。
- 白話解釋只能用講者或講義自己說過的說法；講者沒解釋、讀者又需要的詞，進名詞小辭典。
- 沒把握的譯名保留英文，不要硬翻。

**讀者層級不放寬 0.3。** 層級改變的是「怎麼說」，不是「能說什麼」。

#### 0.11 名詞小辭典（非講者內容）

讀者層級不是 `self` 時，`l2n render` 會在 `### References` 正前方產出這一節的骨架，
標題固定是 `## 名詞小辭典（非講者內容）`。

骨架列出候選詞（JSON 的 `unverified_terms`，以及從標題、摘要、takeaways、條列抽出的縮寫），
每條一個待寫的佔位，整節帶一個 `<!-- ai-draft -->`，寫完連標記一起刪。

- 標題一字不改，位置固定在 `### References` 之前。它**不是**必備章節（R1 不查它），但
  `student` 與 `public` 必須有（R14）；`clerk` 選用；`self` 不產生。
- 每條 1 到 2 句白話解釋。**不寫數值閾值、不附文獻**。
- **本文不得引用本節。** 本文寫講者說的話；小辭典只是讓讀者讀得懂那些話。
- 查不到可靠說明的詞就刪掉那一條；列自 `unverified_terms` 的詞尤其如此——它本來就是
  「查不到」的詞。
- R3、R5、R10、R11 不掃這一節；R12 照掃（譯名錯在哪裡都是錯）；R14 掃它有沒有數值閾值。

### 1. 來源優先序與證據

#### 1.0 OCR 文字住在兩個地方，只有一個是給筆記讀的

| 檔案 | 是什麼 | 筆記階段讀不讀 |
| ---- | ---- | ---- |
| `<stem>.frames_ocr.json` | `l2n ocr` 的**快取**，鍵是影格路徑，用檔案大小與 mtime 判斷要不要重跑 | **不讀。** 它只是為了讓重跑不必再付一次 OCR 的錢 |
| `<stem>.json` 每段的 `frame_ocr` | `l2n ocr` 把快取**併進正式 JSON** 的結果，已經按段落分好 | **這一個才是**擴寫時的來源 |

`l2n ocr <frames 資料夾>` 如果解析不出同層唯一的 stem 就會 exit 2——舊行為會寫出一個
`frames.frames_ocr.json`，快取有了、正式 JSON 一個字也沒有，而擴寫的人要到寫筆記時才發現。
多場講座共用 `frames/` 時改傳 `<stem>.json` 或 `<stem>.frames.json`；`l2n run` 會自己指定 stem。
`l2n scaffold` 建骨架時會把既有的 `<stem>.frames_ocr.json` 併進 `frame_ocr`。

兩個地方的文字**都**只用來決定「要不要打開那張影格」，不可以抄進筆記。


筆記裡的每一個事實、每一個數字、每一個術語，都必須可以追到下列四種來源之一。四者衝突時，**排在前面的決定本文的主說法**——另一種說法不是丟掉，見 1.2：

| 順位 | 來源 | 說明 |
| ---- | ---- | ---- |
| 1 | **官方講義** | 講者自己準備的投影片檔、handout、論文。最可信。 |
| 2 | **用眼睛看過的影格** | `frames/` 裡的畫面，你實際打開看過的那一張。 |
| 3 | **逐字稿** | ASR 產出，有錯字、有斷句錯誤，但語意結構可用。 |
| 4 | **OCR 文字** | `frames_ocr.json`。**只用來決定要打開哪一張影格，絕對不可抄進筆記。** |

OCR 不入文這一條沒有例外。OCR 會把 `L4-L5` 讀成 `14-15`、把 `T2` 讀成 `12`，而且錯得很像真的。它的唯一用途是搜尋與定位。

#### 1.1 不可證實的術語

逐字稿聽到一個術語，但講義查不到、影格看不到、也查不到任何可驗證的出處時：

1. 把它寫進 canonical JSON 的 `unverified_terms`。
2. 在 References 區列出來，標明「未寫入本文」。
3. **本文只寫講者實際描述的內容，用可證實的敘述性說法代替那個名字。**

**正例（去識別化）**：一場 MSK MRI 判讀會裡，講者提到環繞 femoral head-neck junction 一圈的骨刺「有個 sign 的名字」，並自述典故跟小時候跳繩有關。逐字稿把那個名字記成 `Schrodinger's lobe sign` 與 `shedding loss sign` 兩種拼法，兩者都查不到。正確處理是：

- References 列出 `Schrodinger's lobe sign（未寫入本文）`。
- 本文寫講者同一段裡自己用過的可證實說法——「繞一圈的 spur」「頸圈」，並對應文獻上的 **collar (ring) osteophyte**。
- 註腳記錄「講者確實提過一個 sign 的名字，但無法還原，本筆記不代為認定」。

反面做法有兩種，都不行：直接把 `Schrodinger's lobe sign` 當成術語寫進本文（製造一個不存在的名詞），或者完全不提（丟掉講者真的說過的資訊）。

#### 1.2 來源不一致時，分三種處理

| 情況 | 本文怎麼寫 | 另外做什麼 |
| ---- | ---- | ---- |
| **ASR 錯**（逐字稿把講者說對的話聽錯） | 改成對的 | References 的 corrections 表列一列（2.4） |
| **講者口誤，或講者說的與講義不一致** | 照錄講者說的，加註「講者口述如此，講義為 X」 | 不替講者選邊、不更正 |
| **講義內部不一致**（前後數字不同、表號錯置） | 兩種寫法並列，加註出處 | 不選邊 |

判斷是 ASR 錯還是口誤，看有沒有別的證據：講義、影格、同一場講者自己的其他句子。
沒有證據時當作口誤處理——照錄比替講者改更安全。

#### 1.3 影格說明只寫有依據的東西

影格說明的依據只有兩個：**該影格所在段落時間區間內的講者口述**，以及**講義上的圖說**。
兩者都沒有提到的屬性——窗位（肺窗、縱隔窗）、投影方式（PA、AP、仰臥）、側別、病灶位置、
形狀、數量、器材（導管、電極、金屬物）——**一律不寫**，即使你在畫面上看得到。

- 講者展示的是**一個病例**；講者的一般陳述才是一般特徵。兩者不同就分開寫，各附時間碼，
  不要把一般陳述掛成某一張影格的說明，也不要把那一例的樣子寫成疾病的特徵。
- 影格說明不得出現「推測」「推斷」（R13）。講者自己這樣說，就用「」照錄。
- 講義圖說與講者口述矛盾時，照 1.2 第二列處理。

### 2. 引用與綜整

#### 2.1 原話用「」標示

講者的話逐字重現時，一律包在「」裡，或寫成引用區塊，並附時間碼。讀者要能一眼分辨哪一句是講者說的、哪一句是你整理的。

`--style faithful` 時，**Note 的每一節至少要有一句標示為原話的引用**。這是機器檢查項（R6）。

#### 2.2 禁止原句直貼

把逐字稿的句子原封不動搬成條列，不算筆記。

「綜整」的意思是：用講者的**推理鏈**重述，不是用他的**句子**重述。一段三分鐘的說明，講者的推理可能是「因為 A，所以在 B 的情況下要選 C，除非 D」——寫下這四步，不要寫下他講這四步時說過的一百二十個字。

真的需要保留原句時，就標成引用（見 2.1）。標了就合法，沒標就是違規。這是機器檢查項（R5）：Note 本文裡出現 40 字以上（去空白標點後）與逐字稿完全相同、又沒有標示為引用的片段，就會被報出來。

**展開電報句：補講者隱含的主詞與連接詞，說出比較對象；不補講者沒說的因果。** 講義條列與口語片段常是名詞堆疊（「腦室周圍、橢圓形、垂直」）。寫成句子時，
補上講者隱含的主詞與連接詞，說出比較對象（「病灶位於腦室周圍，呈橢圓形，長軸與腦室壁垂直」）；
**不補講者沒說的因果**。展開是讓句子讀得懂，不是讓它說得更多。0.4 的 150 字上限照舊。

**本文的推論只認兩種記號。** 推理鏈是講者的推理鏈；你自己往下推的那一步，要在句首或條列開頭標出來：

| 記號 | 用在哪裡 |
| ---- | ---- |
| `[推論]` | 講者沒說、由講者說過的話推得出來的結論 |
| `[本筆記整理]` | 講者沒排、你自己做的歸納、排序或判讀流程 |

**沒有記號的推論就是編造**（0.3）。`（推論）`、【推論】或放在句尾都不算；題目裡的 `[推論]` 仍照 5.2.1。

#### 2.3 講者的能力邊界照錄

講者說「我不知道」「我沒辦法回答」「我沒有經驗」「這個我不確定」時：

- **照錄**，而且標成原話。
- **絕對不可以用模型自己的答案補上去**，更不可以用講者的語氣寫出他沒說過的結論。

**正例（去識別化）**：同一場判讀會裡，有人問「ankle ligament 如果是 complete tear，追蹤影像上會不會長回來」。講者的回答是：

> 「這個我沒有辦法回答，因為我沒有經驗說 follow 以後有沒有長回來。」

正確的筆記寫法是把這句原話留著，加一句「他建議這要靠臨床端實際追蹤，不由他推測」，然後——這是重點——把這一段**單獨留成一節**，因為它示範了判讀者該有的界線：沒有經驗的事就說沒有經驗。

如果模型在這裡自己去查文獻補一段「根據某研究，complete tear 的癒合率是……」，那份筆記就從「這位講者怎麼想」變成「模型怎麼想」，而讀者無從分辨。這是最嚴重的一種污染，因為它看起來是加值。

#### 2.4 ASR 錯字：本文改對，References 列表

逐字稿的同音錯字一定要在本文裡改成正確的寫法，同時在 References 的 corrections 表裡列出來，每一列都要有 `heard`（聽成什麼）、`correct`（正確是什麼）、`source`（怎麼判定的）。

改而不列，讀者日後對照逐字稿會以為筆記寫錯；列而不改，筆記本身就是錯的。兩件都要做。這是機器檢查項（R4）。

這一條只管 **ASR 聽錯**。講者自己口誤、或講者與講義不一致，不是 ASR 錯，照 1.2 照錄加註，不改。

#### 2.5 正確性清單（機器抓不到，逐條守）

下面每一條都是撰寫者讀起來「沒錯」、只有回到來源逐句比對才抓得到的錯。例子為說明用途自擬。

| # | 錯誤型態 | 規則 | 反例 | 正例 |
| ---- | ---- | ---- | ---- | ---- |
| 1 | **說過頭** | 講者的「通常／可能／大多／少數／我覺得」照錄，不改成「一定／只有／絕不／會」 | 講者：「這個通常會增強」-> 筆記：「此病一定增強」 | 「講者說這類病灶通常會增強」 |
| 2 | **數量詞漏掉** | 「約 10%」「少數」「大多數」一個都不能丟 | 講者：「大概一成會增強」-> 筆記：「不增強」 | 「約一成會增強（00:12:30）」 |
| 3 | **夾帶因果** | 相鄰兩句不等於因果；不自加「所以」「因為」「因此不能排除」 | 「黏膜會增強，所以要做脂肪飽和」（講者說脂肪飽和是為了看骨頭） | 兩件事分開寫，各附時間碼；要推論就標 `[推論]` |
| 4 | **替講者排順序** | 講者說「X 可以長得像 Y」，就寫「Y 也可能是 X」，不寫「先想 X、先排除 X」；自己排的流程標 `[本筆記整理]` | 「本講座教的判讀順序是先找阻塞點」（講者沒排順序） | 「[本筆記整理] 依講者提到的順序：…」 |
| 5 | **單一示範當通則** | 講者示範的一個病例是那一例；講者的一般陳述才是一般特徵 | 「這一例均勻增強」-> 「此病均勻增強」 | 「講者展示的這一例呈均勻增強（00:20:05）」 |
| 6 | **加講者沒說的判準或評語** | 不加「最有區分力」「最快的分法」「依年齡判斷」 | 「這是最快的鑑別方法」（講者沒比較快慢） | 只寫講者說的判準 |
| 7 | **比較對象錯置** | 先確認講者比的是哪兩樣 | 講者比「聽力喪失 vs 眩暈」-> 筆記寫「壓迫效應 vs 眩暈」 | 「講者比較聽力喪失與眩暈兩種表現」 |
| 8 | **條件範圍被改** | 條件句管到哪裡就寫到哪裡；不加排他的「才」 | 「發燒時才需要追蹤」（講者說「發燒時要追蹤」） | 「發燒時要追蹤」 |
| 9 | **英文連接詞翻錯**（英文講座、英文講義） | although＝雖然／不過，不是「因為」；where＝其中；when＝在…時 | although 譯成「因為」 | 「雖然…，不過…」 |
| 10 | **硬配表格** | 講者沒有一一對應的內容，不做成逐列對應的表 | 講者把影像表現分三段，筆記硬配成四期的表 | 照講者的三段寫 |
| 11 | **逐例說明被歸納成通則** | 講者逐病、逐例說的事，不在 Evergreen 或 Summary 寫成通則；要歸納就標 `[本筆記整理]` | 「各病都靠切片確診」（講者只說了其中兩個） | 逐病照錄 |
| 12 | **題幹條件不一致** | 題幹的敘述要對每一個子題都成立 | 「三個病例 CT 都是高密度」，其中一例講者說等密度 | 題幹只寫三例共有的條件 |
| 13 | **年齡 decade** | Nth decade＝(N-1)0 到 (N-1)9 歲，並附原文序數；younger than 35＝未滿 35 歲 | sixth decade -> 「60 多歲」 | 「50 到 59 歲（sixth decade）」 |

其中第 1、2、3、4、5、7、8 類，`l2n review-prompt` 會列給獨立驗收的人逐項找（見本規範後半的獨立驗收一節）。

### 3. 隱私

#### 3.1 與會者與病患姓名一律不入文

逐字稿裡出現的與會者姓名、病患姓名、家屬姓名、任何私人個體的名字，**不寫進筆記，也不寫進 canonical JSON**。一律以角色或臨床描述取代：

| 逐字稿裡的樣子 | 筆記裡該寫成 |
| ---- | ---- |
| 某位與會醫師的姓名 | 與會醫師 |
| 病患全名 | 57 歲女性 |
| 「○○○ 醫師剛剛問的那個問題」 | 「提問者剛剛問的那個問題」 |

病歷號、身分證字號、電話、電子郵件一律不入文。`l2n check note` 會用 profile 的 `privacy.toml` 比對每一行（R7），但那只擋得住格式固定的識別碼，人名擋不住——人名靠這一條規則。

#### 3.2 講者姓名只採三種來源

講者姓名只能來自：**檔名**、**官方講義**、**畫面上的名牌或標題**。

**不可以只憑逐字稿認定講者姓名。** 中文人名的 ASR 錯誤率很高，而一旦寫錯，這個錯誤會跟著筆記一路傳下去，而且看不出來是錯的。檔名沒有、講義沒有、畫面沒有，就寫「講者」。

#### 3.3 參與者面板與聊天室的影格

線上講座的錄影常有幾分鐘畫面是參與者面板或聊天室，上面是與會者的真名與電子郵件。
這些影格做 OCR，名字就進了 JSON 的 `frame_ocr`。

- **OCR 前先排除**：`l2n ocr <stem>.json --skip-frames <glob 或時間範圍>`
  （例：`--skip-frames 00:52:00-00:58:30`），可重複給。
- 已經做過 OCR 的，**用同樣的 `--skip-frames` 再跑一次 `l2n ocr`**：符合的影格會從 `frame_ocr`
  與 OCR 快取 `<stem>.frames_ocr.json` 一起清掉，再重跑 `l2n check json`。
  只手動清空 JSON 的 `frame_ocr` 不夠，快取裡的文字下次 `l2n scaffold` 會再併回來。
- `l2n check json` 看到 `frame_ocr` 裡有電子郵件樣式的文字會報 warning（`frame_ocr_email`）。
  人名它抓不到，靠這一條規則。

### 4. 好筆記長什麼樣

達到上面全部規則、但讀起來沒有價值的筆記是存在的。這一節描述通過之後應該長成的樣子。

- **Evergreen**：**一句話總結本課程內容**，指得回時間碼。不是 `takeaways_zh[0]` 照抄，也不是半句逐字稿；講者沒說、你自己做的歸納或排序，標 `[本筆記整理]`（見 4.1）。
- **Summary**：直接引用 `takeaways_zh`（見第 7 節），不重寫。條列本身要**明確指出容易混淆的觀念**——「A 與 B 常被混用，差別在 X」這種句子的價值，高於十條互不相干的重點。
- **講者骨架**：每段一行，動詞開頭，寫講者**做了什麼**（見第 6 節）。時間碼與佔比是機器算的，不要改。
- **Note**：以**講者的推理鏈**重述，不是逐字重述。每一節都要嵌一張影格——沒有畫面的段落，三個月後沒有人讀得懂。
- **References**：corrections 表、unverified_terms、來源區塊，三者齊全。這是筆記可被稽核的部分。
- **題目**：3 至 5 題，跨段出題，至少一題是標了 `[推論]` 的推論題，答案收在 `> [!answer]-` 裡（見第 5 節）。問理由與邊界，不問名詞定義。
- **學習驗證**：至少一項，而且是讀者能自己判斷通過與否的項目。
- **`# 閱片`**（radiology profile 的模板才有）：**只在講座含影像判讀時保留，否則刪掉整節。**
  callout 的固定欄位沒有素材時寫 `N/A（原文未涵蓋）`（0.3），寫法依第 1.3 節。
- **名詞小辭典**：讀者層級需要時才有（0.11）。

#### 4.1 一句話總結本課程內容（Evergreen 唯一的判準）

**擴寫的第一件事是先寫 Evergreen，不是最後補。** 先把它寫出來，整份筆記才有一個
能檢查其他段落的軸；留到最後寫，就只會變成把 `takeaways_zh[0]` 抄一遍。

1.4 起 Evergreen 的定義是：**一句話總結本課程內容**，而且指得回時間碼。判斷方法：
**沒聽過這場講座的人讀了這一句，說得出這場在講什麼、講者的結論是什麼嗎？**

它是總結，不是延伸。講者沒說的抽象、你自己做的歸納或排序，一律標 `[本筆記整理]`——
1.3 版以前要求的「可遷移原則」常常就是在這一步替講者多說了一句話（見 2.5 第 4、11 類）。

以下例子為說明用途自擬，與任何真實筆記無關。

**反例（半句逐字稿）**

> 「所以我一直在講的就是說，這個東西其實」

它是逐字稿裡被切斷的半句話，沒有主詞也沒有結論；讀者讀完不知道這場講座在講什麼。
沿用骨架的 `takeaways_zh[0]` 也是同一類：那是某一段的一個重點，不是整場的總結。

**正例（一句話總結）**

> 「講者以三個誤判病例說明：同一個影像徵象要先確認掃描條件，再判斷它代表什麼（00:03:10、00:41:20）。」

拿掉這一句以外的整份筆記，讀者仍然知道這場講座的範圍與講者的結論，而且每一個字都找得到出處。

兩者的差別不在「有沒有改字」，而在**有沒有真的讀完整場、說出講者的結論**。
機器判不出這一步：R10 只看字元有沒有被換掉，把反例加幾個字就能通過。
**R10 通過不代表 Evergreen 合格**，請對照這一節與 0.9 的坡道自檢再確認一次。

#### 4.2 frontmatter 只定語意

frontmatter 的欄位名稱與有哪些欄位，全由 profile 或個人 overlay 的 `note.frontmatter.yaml`
決定；規範只定三件語意：

- 完成狀態、消化層級這類欄位，**只有讀者能往上改**；模型產出一律填最低的那一級（0.5）。
- 講者、講題、日期只取 3.2 的三種來源；查不到就留空或寫「來源待查」，不憑印象補。
- 講義檔名與版本要記，就記在 References（profile 開 `references.record_handout` 時，
  `render --expand-prompt` 會提醒）。

### 5. 回看：題目不得留空

#### 5.1 為什麼是答題，不是重讀

重讀是低效益的複習方式，答題是高效益的那一種。Karpicke 與 Blunt（2011）的實驗裡，先答過題的人一週後的保留量高於反覆重讀的人；Dunlosky（2013）把 practice testing 列為 high utility、把 rereading 列為 low utility。

所以 `## 題目` 不是裝飾，它是這份筆記日後唯一會被真正使用的一節。**它不得留空**，骨架已經先放好草稿，擴寫時只能改寫，不能刪成空節。

#### 5.2 題數與題型

- **3 至 5 題**，而且**跨段出題**（交錯）。一段一題的題目，翻到那一節就答得出來，那還是重讀。
- **至少一題是推論題，標上 `[推論]`**。推論題問的是主張的邊界，句型長這樣：

  > 若病人有 A 但沒有 B，這篇的結論還成立嗎？

  不是這樣：

  > X 的定義是什麼？

  定義題翻筆記就有答案，它量不到任何東西。

#### 5.2.1 `[推論]` 的寫法只有一種

半形方括號、裡面兩個字「推論」、**放在題目文字的最前面**，號碼之後：

```markdown
1. [推論] 若某個案例具備 A 但缺少 B，這篇的結論還成立嗎？
```

R9 只認這一種寫法。`（推論）`、`[推理]`、`【推論】`，或把標記放在句尾，都不算。
不是為了刁難格式：可以放在任何地方的標記，寫的人會停止放，讀的人會停止看見。
機器認得這一種，就有一件事是量得到的。

#### 5.3 答案一律收合

每一題的答案寫在 `> [!answer]-` 收合區塊裡，並附對應時間碼。先自己答完、再展開，這是這個語法存在的唯一理由；答案攤在題目下方，等於沒有出題。

`l2n check note` 的 R9 會數題數、找 `[推論]` 標記，1.4 起也檢查**每一題到下一題之間都有自己的** `> [!answer]-`（warning）。它數得到形狀，數不到題目好不好——好不好靠 5.2 與 2.5 第 12 類（題幹條件要對每個子題都成立）。

### 6. 講者骨架（Reverse Outline）

`## 講者骨架` 這一節由 `l2n render` 機械生成：每段一行，欄位是**時間碼 ｜ 佔比% ｜ 一句話**。時間碼與佔比來自 JSON，模型不得更動；模型只寫第三欄那一句。

#### 6.1 寫「做了什麼」，不寫「講了什麼」

一句話，**動詞開頭**，描述講者在那一段**做的事**：

| 可以 | 不可以 |
| ---- | ---- |
| 用一個誤診案例開場，佔 6% | 講了椎間盤分級 |
| 把兩個常被混用的名詞並排比較 | 介紹第二個主題 |
| 收掉前面的假設，改用另一組判準 | 第三部分 |

差別在可遷移性。「用一個誤診案例開場」是一個你下次也可以用的動作；「講了椎間盤分級」只是把目錄再抄一次，讀者已經從段落標題知道了。

#### 6.2 坡道在開頭 5 至 8%

開頭那 5 至 8% 是**坡道**：講者在那裡交代這件事為什麼值得講、前人卡在哪、既有做法哪裡不夠。

坡道是 Evergreen 的原料。離開這場講座仍然成立的那句話，通常長在坡道，不在正文的細節裡。所以骨架先把佔比印出來——找得到坡道，才寫得出 Evergreen（見 0.9）。

#### 6.3 首段與末段不呼應，是分段的問題

寫完骨架之後看一次第一行與最後一行。**講者幾乎都會在結尾回到開場的那個問題**；如果兩端看起來毫不相干，多半不是講者跳掉了，而是**坡道被併進了第 2 段**。回頭檢查分段，不要在筆記裡硬把兩端接起來。

### 7. 摘要不重寫，補充六選一

#### 7.1 Summary 直接引用 `takeaways_zh`

Summary 的條列**直接用 JSON 的 `takeaways_zh`**，不要換句話說。JSON 那一層已經過 `l2n check json`，重寫一次只會讓筆記與 JSON 對不起來，而且沒有人看得出來是哪一層出錯。

筆記相對 JSON 只新增三樣東西，其餘一律引用：

1. **講者骨架**（見第 6 節）
2. **跨版本對照**（同一主題的新舊指引、新舊分級差在哪）
3. **閱片連結**（連到自己 vault 裡的影像或病例筆記）

這三樣是 JSON 裡沒有、也不該有的東西：它們是這份筆記與你其他筆記之間的關係，不是這場講座的內容。

#### 7.2 講者補充採六選一

逐字稿裡講者的補充、岔題、舉例，**只有符合下列六種之一才寫進筆記**：

| 類型 | 判準 |
| ---- | ---- |
| 界定概念 | 把一個模糊的名詞劃出邊界 |
| 後果嚴重 | 說明做錯會發生什麼，而且後果具體 |
| 與認知相反 | 明白推翻聽眾原本會有的直覺 |
| 遞進缺環 | 補上推理鏈裡少掉的那一步 |
| 轉折 | 講者自己收回或修正前面說過的話 |
| 多面向印證 | 用另一種證據支持同一個結論 |

六種都不符合的補充，**只在 JSON 留一個時間碼**，本文不寫。想回去聽的人找得到，不想聽的人不會被它佔掉版面。

#### 7.3 `questions_zh` 與四段弧

分段階段可以把跨段題目寫進 JSON 的選填欄位 `questions_zh`（每題含 `text` 與 `segments` 索引陣列，索引就是 `segments[].index`，1 起算）。`l2n render` 會拿它當題目節的草稿；沒有這個欄位時骨架自己從段落標題生。

寫 `overall_summary_zh` 時順手檢查**四段弧**：**坡道、背景、正文、昇華**。四段都指得出來，摘要才算涵蓋整場。

**缺哪一段就照實寫，不要補**。最常缺的是昇華——通常表示結尾被 Q&A 吃掉了，那是事實，不是筆記的缺陷。

四段弧的檢查結果寫進 JSON 頂層的選填欄位 `editorial_notes_zh`（字串陣列）。`l2n check json`
接受它，`l2n render` 把它印在 Summary 的一個摺疊 callout 裡（`> [!note]- 編輯備註（四段弧等，非講者原話）`）。

### 8. 課程首頁的摘要不得空

一門課的首頁（`l2n hub` 產出的 `課程首頁.html`）可以讀同資料夾下的選填檔 `_course.json`，把摘要印在卡片上方：

```json
{
  "question": "本系列在回答的問題（一句話）",
  "start_with": "最該先看的一場",
  "no_common_thread": false
}
```

兩件事都要寫：

- **本系列在回答的問題**：把整門課當一場講座，它的 Evergreen 是什麼。
- **最該先看的一場**：新手進來第一個該點哪一張卡。

一排卡片本身不是摘要。十二張卡片排在那裡，讀者要一張一張點開才知道該從哪裡開始，那跟沒有首頁差不多。

**真的沒有共同主線時，就寫出來**：把 `no_common_thread` 設成 `true`，首頁會印「本系列各場主題獨立，無共同主線」。這是一個答案，不是一個缺漏；留白才是缺漏。

## 機器可檢查

這一部分由 `l2n check note <stem>.json --note <stem>.v4.md` 執行。報告的第一行會印出這份規範的版本字串（`guideline_version: 1.4`），接著每一個 finding 一行：

```
<severity> R<n> <location>: <message>
note: N errors, M warnings
```

exit code：`0` 全過、`1` 只有 warning、`2` 有任何 error。

| 規則 | 嚴重度 | 內容 |
| ---- | ---- | ---- |
| **R1** | error | 七個必備章節全部存在，而且順序正確：`# Evergreen Note`、`# Summary`、`## 講者骨架`、`# Note (layer 1-3)`、`### References`、`## 題目`、`## 學習驗證`。 |
| **R2** | error | 筆記裡每一個 `![[...]]` 嵌入都解析得到實際存在的檔案（相對於筆記本身）。 |
| **R3** | error | `unverified_terms` 的每一項都出現在 References，而且都不出現在 Note 本文。 |
| **R4** | error | References 的 corrections 表存在，而且每一列的 `heard` 與 `correct` 都不是空的。 |
| **R5** | warning（profile 設 `guideline.transcript_paste = "error"` 時為 error） | **Evergreen Note、Summary、Note 本文、`## 題目`（含答案區）、`# 閱片`**裡沒有任何一行，含有 40 字以上（去空白與標點後）與逐字稿完全相同、又沒有以「」或引用區塊標示的連續片段。`# 閱片` 全是 callout 行，那裡只豁免「」片段與 `> 「…」` 這種整行引用。 |
| **R6** | faithful 風格下為 error；concise 風格下跳過 | 每一個段落章節至少有一行是「」包住的原話或引用區塊。 |
| **R7** | error | 沒有任何一行符合生效 profile 的 `privacy.toml` 所列的模式。 |
| **R8** | warning | Note 章節與 `# 閱片` 內沒有 `N/A`、`不適用`、`無資料`、`（略）` 之類的補位字串。沒素材就刪掉那一節（見 0.3）。`# 閱片` 內一字不差的 `N/A（原文未涵蓋）` 不報；同一個字串寫在 Note 章節照報。 |
| **R9** | warning | `## 題目` 節至少有 3 題，而且至少一題的**題目文字開頭**是 `[推論]`；每一題到下一題之間都有 `> [!answer]-`。少於 3 題、找不到 `[推論]`、某一題沒有收合答案，各報一條（格式見 5.2，寫法見第 5 節）。 |
| **R10** | warning（profile 設 `guideline.unexpanded = "error"` 時為 error） | 沒有任何一個段落章節的本文，有 **60% 以上的字元仍然逐字來自** `l2n render` 用同一份 JSON、同一個 style 重新產出的骨架。完全沒動過就是 100%。Evergreen 仍是骨架那一句時同樣報。門檻可由 profile 的 `outputs.toml` 以 `check.r10_ratio` 覆寫。 |
| **R11** | warning | 同一句話（去空白標點後 25 字以上）不會逐字出現在兩個以上的章節。掃 `# Evergreen Note`、`# Summary`、`# Note (layer 1-3)`、`## 題目`、`## 學習驗證`；`## 講者骨架`、`### References`、名詞小辭典與 frontmatter 不掃。 |
| **R12** | warning（profile 設 `guideline.forbidden_terms = "error"` 時為 error） | **禁用譯名。** 範圍：frontmatter 之後每一行（含 `# 閱片` 與名詞小辭典），`### References`、程式碼圍欄、「」片段除外。清單來自生效 profile 的 `[check.forbidden_terms]`：`always` 層出現就報；`context` 層要同一行或該段逐字稿含它的英文線索才報。訊息：`warn R12 <筆記>:<行>: 「錯字」 -> 「正譯」 (English) [always]`。generic 不帶清單，所以不報。 |
| **R13** | warning | **影格說明裡的推測。** 範圍：`# 閱片` 區，加上 Note 本文每個 `![[…]]` 嵌入行之後緊接的那一段（到空行為止）。先扣掉「」片段，再找「推測」「推斷」。訊息：`warn R13 <筆記>:<行>: 「推測」 in a frame description; ...`。 |
| **R14** | warning | **名詞小辭典。** `note.reader` 是 `student` 或 `public` 而 `## 名詞小辭典（非講者內容）` 不存在，報一條；該節內任何一行出現數值閾值（數字加 `%`、`mm`、`cm`、`HU`、`ms`、`歲`、`倍`），或比較符號（`<`、`>`，以及全形的小於等於、大於等於號 U+2264、U+2265），每行報一條。HTML 註解與行首的 `>` 不算。訊息：`warn R14 <筆記>: note.reader is student, so the note needs the section ...`；`warn R14 <筆記>:<行>: the glossary carries a threshold or a number with a unit (...)`。 |

### R11 的範圍與邊界

**1.3 新增，1.4 沿用（名詞小辭典不掃）。** 盲評裡最扁平的一項發現：同一句話逐字出現在 Summary、Note 本文、
「我應該記住的 3 件事」三個地方，而所有規則都只看單一章節，所以沒有任何一條抓得到。
讀者讀到第三次會開始懷疑這份筆記裡有沒有任何一句是選過的。

- **引用照樣算。** 和 R10 相反：`「」` 與 `>` 引用區塊裡的原話在不同章節重複出現仍然計入
  —— 同一句原話引一次就夠了。
- **`# Evergreen Note` 與 `# Summary` 這一對除外。** 7.1 要求 Summary 逐條引用
  `takeaways_zh`，而 `l2n render` 的 Evergreen 就是 `takeaways_zh[0]`；
  還沒改寫 Evergreen 的筆記會因為「照 render 做的事」被報。那份筆記 R10 已經報過，
  而且說得更有用。只在這兩個章節重複，不報；多出第三個章節，照報。
- **`## 講者骨架` 與 `### References` 不掃**：骨架是每段一行的機器投影；
  References 的工作本來就是把別處出現過的詞再列一次。
- 一句話報一次，不是每出現一次報一次。

### R10 的算法與邊界

**1.3 起（1.4 沿用），R10 從「逐字完全相同」改成「殘留比例」。** 理由是一次四份筆記的盲評：
其中一份在每一節骨架文字的**前面**加了一段自己的推理鏈，骨架原文一個字都沒刪。
去空白之後不再一字不差，1.2 的 R10 因此安靜，但讀者拿到的是同一件事講兩遍。

算法：

1. 用同一份 JSON、同一個 style 重新 render 一次骨架，取出該段的**句子**
   —— `summary_zh` 那一行，以及每一條 bullet 的文字。
2. 兩邊都以 R5 的同一套正規化處理（去空白與標點、大小寫與全半形折疊）。
3. 逐句在筆記該段本文中搜尋，把命中的字元位置標起來。
4. **殘留比例 = 被標起來的字元數 ÷ 本文字元數**，達到 60% 就報。

不計入的東西（分子分母都不計）：

- `「」` 包住的原話與 `>` 引用區塊，以及它們後面那個 `(00:01:02)` 時間碼
  —— 2.1 明文要求原話照錄，照做不該被判成偷懶。
- 章節標題、`(hh:mm:ss - hh:mm:ss)` 時間區間、`![[...]]` 影格嵌入
  —— 那三樣是機器投影出來的，本來就不該動。

Evergreen 是唯一的例外：它的 `「」` 是 render 自己的排版，不是規範要求保留的原話，
所以那一段連引號一起算。

**這一條抓得到的，只是「字有沒有被換掉」。** Evergreen 從「本週某個數據」改寫成
「離開這場講座仍然成立的原則」那一步，機器沒有判準——R10 通過不代表 Evergreen 合格，
請人工對照第 4 節與 0.9 節再確認一次。

### R5 的範圍與邊界

**1.2 起，R5 掃描的範圍從「只有 Note 本文」擴大到讀者會當成結論讀的每一段散文：**
`# Evergreen Note`、`# Summary`（到 `## 講者骨架` 為止）、`# Note (layer 1-3)`、
以及 `## 題目`（含答案區）。

改這一條的理由寫在附錄 A：那份失敗樣態的 Summary 有一條和 Note 本文一樣糟的直貼，
而 1.1 的 R5 看不到它。實地試跑又出現一次同樣的事——五條 Summary 全是逐字稿原句，
`check note` 卻是乾淨的。**「第一部分（人／LLM 遵守）不能只靠第二部分兜底」這句話仍然成立，
但機器能看到的範圍不應該小於讀者會相信的範圍。**

豁免方式不變：「」包住的片段會先被扣掉，整行是引用區塊（`>`）就跳過——
在 `# 閱片` 以外的章節都一樣。**1.4 起 R5 也掃 `# 閱片`**：那一區每一行都是 callout，
「`>` 開頭整行跳過」會讓整區免檢，所以在那裡只豁免「」片段與 `> 「…」` 這種整行引用。骨架本身不會因此被誤報：Summary 引用的是 `takeaways_zh`，
那是模型整理過的話，不是逐字稿裡的句子。

逐字稿以同一套正規化方式處理：去掉空白與標點、大小寫與全半形折疊之後再比對。

| 直貼片段長度（正規化後字數） | 有沒有標成引用 | 結果 |
| ---- | ---- | ---- |
| 39 | 沒有 | 通過 |
| 40 | 沒有 | 報 R5 |
| 120 | 有（「」） | 通過 |
| 120 | 有（引用區塊 `>`） | 通過 |

一行裡被「」包住的片段會先被扣掉再比對，所以「半句標了、半句沒標」的行，只會針對沒標的那半句判定。

逐字稿來源是與 JSON 同名的 `<stem>.srt`。找不到時 R5 跳過，並印一行 warning 說明它跳過了——沉默地不檢查，比不檢查更糟。

### R12 的範圍與邊界

**1.4 新增。** 譯名錯誤是 L3 教科書筆記獨立驗收最常抓到、撰寫者自己讀不出來的一類。

- **清單在 profile，不在程式裡。** radiology profile 的 `outputs.toml` 帶初始清單（附錄 C），
  generic 不帶；個人 overlay 可以在 `[check.forbidden_terms.always]` 或 `.context` 加一個鍵，
  不必重寫整份（表格逐鍵合併）。值是 `{correct, english, cue}`。
- **context 層一定要有線索。** 「栓塞」用在 embolism 是對的，用在 thrombosis 才錯；所以它只在
  同一行或該段逐字稿出現 `thrombo` 時報。沒有 `cue` 的 context 條目會被丟掉。
- **「」不掃**：講者自己說錯就照錄（1.2）。**References 不掃**：corrections 表本來就列著錯字。
- 同一處同時命中 `always` 與 `context`（例：「遠端轉移」）只報一次。
- `l2n check json` 對 `takeaways_zh`、各段 `summary_zh`、`bullets_zh[].text` 跑同一份清單
  （warning，代碼 `forbidden_term`）：Summary 逐字引用 takeaways，錯在 JSON 就會錯在筆記。

### R13 與 R14 的範圍

**1.4 新增。** 兩條都是 warning，管的都是「LLM 必須遵守」已經寫明、而且機器看得到字面的部分：

- R13 找的只有「推測」「推斷」兩個詞。「疑似」「可能是」不在清單上——講者自己常這樣說，
  應該用「」照錄，而把它們列進來會把照錄的人一起報。
- R14 不判斷小辭典寫得好不好，只抓兩件事：該有的時候不在、在的時候寫了數字。

### `check json` 的兩條 1.4 warning

| 代碼 | 內容 |
| ---- | ---- |
| `forbidden_term` | 同 R12 的清單，掃 `takeaways_zh`、`segments[].summary_zh`、`segments[].bullets_zh[].text` |
| `frame_ocr_email` | `frame_ocr` 文字出現電子郵件樣式（`\S+@\S+\.\w+`）；多半是參與者面板或聊天室的影格（3.3） |

### 獨立驗收：機器抓不到的錯誤

`check note` 全過之後，交給**沒參與撰寫**的人或 agent 做獨立驗收：

```bash
l2n review-prompt <stem>.json --note <stem>.v4.md
```

它印出一份交辦書：2.5 其中七類錯誤的清單（說過頭、夾帶因果、替講者排順序、單一示範當通則、
比較對象、條件範圍、數量詞），以及機器能列出位置、但對錯要人判斷的抽查候選——本文每一個數字與
它所屬段落的時間區間、逐字稿與筆記裡提到 decade 的地方、至少 8 句「」引文（附時間碼）、
R12 context 層命中。回報格式是 `PASS` 或 `需修正`，修正清單依嚴重度排序，每條附行號、原字串、
建議改法與時間碼。驗收者唯讀、自己抽來源；修正交回撰寫者；改完由主對話 grep 抽查原字串確實消失。

這一步不影響 exit code，也不是 `check note` 的一部分：它要的是判斷，不是規則。

### 通過 check 不等於寫好了

`check note` 的結尾除了 `note: N errors, M warnings`，還會印兩個數字。
它們不影響 exit code，但**它們才是「有沒有人真的動過這份筆記」的唯一證據**：

```
note: unexpanded_segments=K/N
note: ai_draft_remaining=N
```

- `unexpanded_segments`：殘留比例達到門檻的段落數（R10 數的同一件事）。
- `ai_draft_remaining`：還沒被寫掉的 `<!-- ai-draft -->` 佔位數（講者骨架第三欄、題目答案，
  以及讀者層級不是 `self` 時的名詞小辭典）。1.3 起（1.4 沿用）讀者的兩個空槽與「模型候選」
  不帶這個標記，所以這個數字歸零是模型自己做得到的事（見 0.6）。

**兩個都是 0，才代表每一段都有人（或模型）真的重寫過。**

這一段是 1.2 加的，理由是實測：一個全新上下文的模型只讀 skill 就去擴寫，
只填了講者骨架與題目答案，其餘每一段原封不動，而 1.1 的 `check note` 回報
0 errors 0 warnings。R1 到 R9 全部都可以被一份沒有人寫過的筆記滿足——
它們檢查的是形狀，而骨架的形狀本來就是對的。R10 檢查的是「有沒有動過」。

**骨架直接拿去 check 會每一段都報 R10，那是預期行為**，不是誤報：
`l2n render` 剛產出的檔案本來就還不是筆記。

## 附錄 A：失敗樣態（去識別化）

下面這份筆記是虛構的財經講座筆記，公司名為佔位名稱，內容全部合成。它同時犯了三個錯：Summary 的條列是逐字稿原句倒進來的、ASR 同音錯字沒有校正也沒有列表、Evergreen 是一句被截斷的引用。

它存在的理由是：這三個錯**每一個看起來都不像錯**。排版整齊、字數飽滿、有時間碼、有章節。要靠機器才看得出來。

`l2n check note` 對這份筆記至少會報一個 R5（原句直貼）與一個 R4（corrections 表有一列 `correct` 是空的）。可執行的完整檔案在 `tests/fixtures/appendix_bad_note/`，`tests/test_guideline_appendix.py` 每次都會重跑一次確認它真的還會失敗。

節錄：

```markdown
# Evergreen Note

**「所以我一直在講的就是說，這個東西其實」**

# Summary

- 那我們今天要講的其實就是一個很簡單的觀念，就是說當利率往上走的時候，你手上的那個債券的價格它就是會往下掉，這個是一定的
- 木迪那邊前一陣子有把某幾家的評等做了一個調整，這個大家應該都有看到

# Note (layer 1-3)

## 1、利率與債券價格

(00:00:00 - 00:00:30)

那我們今天要講的其實就是一個很簡單的觀念，就是說當利率往上走的時候，你手上的那個債券的價格它就是會往下掉，這個是一定的。

- 木迪那邊前一陣子有把某幾家的評等做了一個調整，這個大家應該都有看到
- 到窮指數那個成分股的調整其實跟我們剛剛在講的這件事情是沒有直接的關係的，大家不要混在一起看

### References

| heard | correct | source |
| --- | --- | --- |
| 木迪 |  |  |
```

三個錯分別對應到：

- Evergreen 那一句是逐字稿裡被切斷的半句話，它不是一個觀念（違反第 4 節）。
- Note 本文第一行是 50 幾字的逐字稿原句，沒有標成引用（違反 2.2）。Summary 裡那條一樣糟糕的條列，在 1.1 以前機器抓不到；**1.2 的 R5 已經涵蓋 Summary，兩條都會被報出來**。第一部分仍然不能只靠第二部分兜底——機器數得到形狀，數不到這一句值不值得寫。
- 「木迪」是「穆迪」、「到窮」是「道瓊」的同音錯字，本文沒改；corrections 表只列了一列，而且 `correct` 是空的（違反 2.4，R4 會抓到那張殘缺的表）。

正確的寫法，同一段內容應該是：

```markdown
# Evergreen Note

**「利率與債券價格反向：手上部位的風險來自期間長短，不是來自信用評等本身」**

# Summary

- 利率上行時債券價格下跌；影響幅度取決於存續期間，長天期部位受創最深
- 評等機構近期下調部分發行人評等，但講者強調評等變動是結果不是原因
```

### 新增的兩種樣態（1.4）

下面兩段同樣是虛構的醫學講座內容，用來說明 2.5 的第 1 類與第 3 類。**機器一條都不會報**——它們只能靠
獨立驗收（`l2n review-prompt`）抓。

**樣態二：說過頭。** 逐字稿是「這種病灶大部分不會增強，大概一成左右會有一點點邊緣增強」。

```markdown
- 此類病灶不增強，可藉此與腫瘤區分
```

錯在兩處：「大部分不會」被寫成「不會」，「約一成會邊緣增強」整個漏掉；後半句「可藉此與腫瘤區分」
講者根本沒說。正確寫法：

```markdown
- 講者說這類病灶大多不增強，約一成有輕微邊緣增強（00:18:40）
```

**樣態三：夾帶因果。** 逐字稿前後兩句是「正常黏膜本來就會增強」「我們這個 protocol 會加脂肪飽和」，
講者在後面才說加脂肪飽和是為了看顱底骨頭。

```markdown
- 正常黏膜會增強，所以要加脂肪飽和
```

兩句相鄰被接成了因果，而講者給的理由是另一個。正確寫法是兩件事分開寫、各附時間碼；
真的要寫推論，就標 `[推論]`：

```markdown
- 講者提醒正常黏膜本來就會增強（00:22:05）
- protocol 加脂肪飽和，講者說是為了看顱底骨頭（00:24:30）
```
